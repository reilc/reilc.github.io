Picker II

picoCTF • Reverse Engineering • Medium

Challenge Info

  • Platform: picoCTF
  • Category: Reverse Engineering
  • Difficulty: Medium
  • Points: -
  • Tools used: VS Code (for viewing source code), GDB

Goal

Print out the value of the flag.

The relevant logic from the challenge is: 

def win():
  flag = open('flag.txt', 'r').read()
  flag = flag.strip()
  str_flag = ''
  for c in flag:
    str_flag += str(hex(ord(c))) + ' '
  print(str_flag)

def filter(user_input):
  if 'win' in user_input:
    return False
  return True

while(True):
  try:
    user_input = input('==> ')
    if( filter(user_input) ):
      eval(user_input + '()')
    else:
      print('Illegal input')
  except Exception as e:
    print(e)
    break

Attempts

First Attempt

Seeing that I was able to provide my own input, I wanted to call the win function without literally typing in win since it'll get filtered out.

I tried using the following variations, all of which are different encodings of the string win:

  • \x77\x69\x6e
  • 0x77 0x69 0x6e
  • bytes.fromhex('77696e').decode('utf-8')

However, they all returned: 

'str' object is not callable

After reasoning about why I kept getting the same error, it turns out that after the encodings are parsed, the eval() function sees: 

'win'()

So it looks as though it's trying to call a string instead of a function.

While I was able to get win past the filter, I ended up with the string object, not the function.

Solution

After taking time to learn more about Python and functions, I eventually stumbled upon globals() and how it could be used in this context.

Since globals() is a dictionary mapping every name in the global namespace, which includes win, we're able to access and call the win() function through globals().

But first, I had to figure out where in globals() win was. That way I could access it directly since globals() returns a dictionary data structure.

Using the program, I was able to do: 

print(globals())

By doing this, I noticed: 

'win': <function win at 0x733395e6b040>

I counted its index, which I double-checked was correct by doing: 

print(list(globals().keys())[13])

This returned: 

win

Now that I was accessing win through globals(), I entered: 

list(globals().keys())[13]

However, this once again gave me the 'str' object is not callable error from before.

After learning from my previous attempt, I knew I was making the same mistake. eval() was once again seeing: 

'win'()

After some thinking, I noticed that the entry from before: 

'win': <function win at 0x733395e6b040>

also included a value: the actual function that win points to.

So instead of entering: 

list(globals().keys())[13]

I entered: 

list(globals().values())[13]

and got back a bunch of hex: 

0x70 0x69 0x63 0x6f 0x43 0x54 0x46 0x7b 0x66 0x31
0x6c 0x37 0x33 0x72 0x35 0x5f 0x66 0x34 0x31 0x6c
0x5f 0x63 0x30 0x64 0x33 0x5f 0x72 0x33 0x66 0x34
0x63 0x37 0x30 0x72 0x5f 0x6d 0x31 0x67 0x68 0x37
0x5f 0x35 0x75 0x63 0x63 0x33 0x33 0x64 0x5f 0x30
0x62 0x35 0x66 0x31 0x31 0x33 0x31 0x7d

This proved that the win() function was called since printing out hex is what the function eventually does.

From here, I decoded the hex using CyberChef and got the flag.

Afterthoughts

The solution from picoCTF was much more straightforward and less complicated than the approach I took.

Their exploit was: 

print(open('flag.txt', 'r').read())#

which makes a whole lot of sense considering the hint they gave:

Can you do what win does with your input to the program?

After seeing the solution, I'm taken back by how simple the problem should've been. I feel like I made it a lot harder than it should've, but all's well that ends well, I guess...

I really wish I tinkered around more and thought about entering Python, especially after I learned about what eval does.
